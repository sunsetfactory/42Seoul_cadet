## ex00

### 다형성

- `virtual` 키워드를 사용하면, 해당 함수가 가상함수임을 명시한다.
- 가상함수는 상속받은 클래스에서 재정의할 수 있다.

### Virtual Table

- 가상함수를 사용하면, 가상함수 테이블(virtual table)이 생성된다.
- 가상함수 테이블은 가상함수의 주소를 담고 있는 테이블이다.
- 컴파일 단계에서 가상함수 테이블이 생성되며, 가상함수 테이블은 객체의 주소를 가지고 있다.
- 가상함수 테이블은 객체의 주소를 가지고 있으며, 객체의 주소를 통해 가상함수 테이블을 참조한다.

### 과제 내용

- `makeSound()` 함수를 가상함수로 선언하고, 상속받은 클래스에서 재정의한다.
- `makeSound()` 함수는 각 동물의 울음소리를 출력한다.

### WrongAnimal 클래스

- `WrongAnimal` 클래스는 가상함수를 사용하지 않아야 한다.
- `WrongAnimal` 클래스의 `makeSound()` 함수는 가상함수가 아니므로, 상속받은 클래스에서 재정의할 수 없다?
  - 재정의는 가능하고 실제로 해당 멤버함수의 호출 또한 가능하다.
  - 하지만 가상함수가 아니기 때문에 동적 바인딩이 아닌 정적 바인딩이 일어난다.

### 동적 바인딩

- 동적 바인딩은 런타임에 함수를 호출할 때 사용된다.
- `virtual` 키워드를 사용하면 컴파일 단계에서 가상함수 테이블이 생성되고, 실행 시 이 테이블의 주소를 참조하여 함수를 호출하게 된다.
- 즉, `Animal` 객체로 `Cat`, `Dog` 객체를 가리키고 있을 때 `virtual` 키워드를 사용하지 않으면 컴파일 단계에서는 `Animal`의 `makeSound()` 함수를 호출하게 된다.

### Brain 클래스

- `Brain` 클래스를 만들어서 deep copy를 구현한다.
- Deep copy는 객체를 복사할 때, 객체의 멤버 변수가 가리키는 메모리까지 복사하는 것을 의미한다.
- Deep copy를 구현하기 위해서는 복사 생성자와 대입 연산자 오버로딩을 구현해야 한다.

## ex03

### 용어 정리

- 정의: 식별자(identifier)를 실제로 구현하거나 인스턴스화 하는 것.
- 선언: 식별자(변수 또는 함수 이름) 및 해당 타입의 존재를 컴파일러에 알려주는 명령문.

### Include 방식

- 우리가 사용하던 include 방식은 정의를 가져오는 것이다. 이는 컴파일러에게 해당 클래스의 구현을 알려주는 것.
- 전방선언은 선언만 가져오는 것이다. 이는 컴파일러에게 해당 클래스의 존재만 알려주는 것.

### 전방선언 사용 이유

- 전방선언을 사용하는 이유는 헤더 파일의 순환 참조를 방지하기 위함이다.
- 헤더 파일의 순환 참조는 헤더 파일이 서로를 include 하고 있을 때 발생할 수 있다. 이는 헤더 파일을 여러 번 include 할 때 발생할 수 있는 컴파일 에러를 방지한다.

### Character 클래스

- 캐릭터는 메테리아를 4개까지 장착할 수 있고, 메테리아를 사용할 수 있다.
- `unequip` 함수를 통해 메테리아를 해제할 수 있다. 단, 메모리 해제는 여기서 해서는 안된다.
- `Floor` 클래스를 통해 메테리아를 버릴 수 있다. 이렇게 한 이유는 서브젝트에서 메테리아를 floor에 버린다고 했기 때문이다.
- `Floor`가 50개까지 메테리아를 가질 수 있게 해놓았다.
  - 이유는 실제 게임에서 일반적으로 바닥에 무한정 아이템을 버릴 수 있게 하기 위함이다.
  - 시간이 지나면 버린 아이템이 사라지게 한다는 점을 고려하여 50개로 제한했다.
